# رفع DareCare إلى GitHub ثم ربط Render

## لماذا لا نستخدم الريبو القديم `project`؟

المستودع `abuhaibra294-hub/project` يحتوي على بوت Python (`bot.py`, `requirements.txt`) ولا يمثل مشروع DareCare. رفع الملفات إليه، أو وضعها على `main`، قد يفسد عملاً قديماً أو ينشر المصدر في مستودع **عام**.

## أسهل طريقة: تشغيل ملف واحد

1. فك ضغط ZIP بالكامل على Windows وافتح مجلد `DareCare.Backend`.
2. شغّل `PUBLISH_TO_GITHUB.cmd` (دبل كليك).
3. عند الحاجة سيثبت Git وGitHub CLI عبر `winget`. إذا لم تتعرف عليهما النافذة بعد التثبيت، أغلقها ثم شغّلها مرة أخرى.
4. سجّل الدخول إلى حساب GitHub `abuhaibra294-hub` من المتصفح عند مطالبتك. لا تكتب توكنات أو كلمات مرور في هذه المحادثة.
5. البرنامج ينشئ **مستودعاً خاصاً جديداً** باسم `DareCare.Backend` ويرفع ملفات المصدر، ثم يفتح رابط GitHub.

البرنامج يرفض الرفع إذا اكتشف ملفات قواعد بيانات محلية أو مفاتيح `.env` أو صور روشتات؛ ويرفض استبدال مستودع موجود مسبقاً أو الدفع إلى مستودع عام. لا يرفع المشروع القديم `project` ولا يلمس تحفيظم.

لو `gh repo create` لم ينجح، جرّب فتح https://github.com/new وإنشاء مستودع خاص `DareCare.Backend` **من غير إضافة README أو .gitignore**. بعدها شغّل CMD مرة ثانية (سينجح لو المستودع ما زال فارغاً).

## بعد الرفع

- افتح `https://github.com/abuhaibra294-hub/DareCare.Backend/actions`، وتأكّد من نجاح أول Workflow (يتطلب .NET 10).
- في Render اختار **New → Blueprint** ثم مستودع `DareCare.Backend`، لأن `render.yaml` في الجذر. أو اختر New Web Service مع Docker؛ لكن يجب إعداد القرص والبيئة يدوياً.
- جهّز SQL Server خارجيًا ومفاتيح JWT وSMTP وCORS من إعدادات Render كأسرار. راجع `docs/RENDER_DEPLOY_AR.md` قبل الدفع لأي خطة مدفوعة.
- ملف `render.yaml` يختار خطة Starter مدفوعة وPersistent Disk؛ هذا ليس نشرًا مجانيًا.
- لا تستخدم بيانات مرضى حقيقية؛ المشروع ما زال نموذج MVP يحتاج Build وSecurity testing على بيئة حقيقية.

## للمتابعة عبر نفس الكمبيوتر

بعد الرفع لأول مرة، ستُنشأ `.git` داخل المجلد؛ يمكن للفريق استخدام Git المعتاد لرفع التحديثات لاحقاً بعد مراجعتها. لو المستودع أصبح فيه تاريخ وتغييرات على GitHub، لا تحاول إعادة إنشاءه من ZIP جديد؛ استنسخه بـ`git clone` ثم أضف الملفات في فرع واعمل Pull Request.
