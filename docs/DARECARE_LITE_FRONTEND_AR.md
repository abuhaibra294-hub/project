# DareCare Lite — واجهة ويب خفيفة على نفس دومين الـAPI

## الفكرة ونطاق النسخة

واجهة RTL عربية صغيرة بدون React أو خادم Frontend منفصل. تُقدَّم بواسطة ASP.NET Core من المسار `/` في بيئتَي `Development` و`Staging`، وتحمّل ملفات CSS وJavaScript من `/assets/darecare-lite.css` و`/assets/darecare-lite.js`.

- **الروابط المتوقعة بعد النشر والتحقق:** `https://project-kv53.onrender.com/` والـAPI على نفس الدومين تحت `/api/v1/`.
- **محليًا:** شغّل تطبيق ASP.NET Core المعتاد وافتح مسار `/` على نفس port الخاص بالخادم.
- **النسخة الخفيفة لا تستبدل تطبيق Flutter** ولا تعد بديلاً جاهزًا للإنتاج الطبي.

## ما يعمل فعليًا من الواجهة

1. عرض الخدمات من `GET /api/v1/services` والبحث في التمريض المعتمد من `GET /api/v1/nurses/search` وتصفية المهارة المطلوبة للزيارة، مع التعامل مع نتائج الصفر وأخطاء HTTP بوضوح.
2. طلب موعد من `GET /api/v1/nurses/{nurseId}/slots` ثم إنشاء الحجز من `POST /api/v1/bookings` باستخدام بيانات الحساب وعنوان الزيارة.
3. تسجيل دخول أي دور عبر `POST /api/v1/auth/login`، وإنشاء حساب مريض عبر `POST /api/v1/auth/register/patient`؛ جلسة JWT/refresh في الذاكرة فقط، لا تُكتب إلى LocalStorage.
4. لوحة المريض: `GET /api/v1/dashboard/me` و`bookings/mine` و`orders/mine` و`prescriptions/mine`، مع طلب إلغاء الحجز وتأكيد/رفض تسعيرة الدواء حسب حالتها.
5. الصيدليات المعتمدة من `GET /api/v1/pharmacies/available`، ورفع ملفات اختبار عبر `POST /api/v1/prescriptions` من حساب Patient فقط. **لا ترفع أي ملفات طبية حقيقية.**
6. لوحة الممرض: الحجوزات (قبول/رفض/بدء/إتمام)، عرض مواعيده وإضافة موعد. لوحة الصيدلية: الروشتات الواردة، تسعير الروشتة وحالات الطلب. لوحة الإدارة: نظرة عامة وطلبات التمريض المعلّقة للقراءة فقط.
7. يتم بناء كل القوائم من بيانات السيرفر الحقيقية باستخدام `textContent`، وليس `innerHTML` مع بيانات HTTP.

## حدود الأمان

- الصفحة وملفاتها على نفس Origin؛ لا نحتاج فتح CORS لمواقع مجهولة.
- الصفحة تستخدم Content-Security-Policy تمنع الـCDNs والـinline scripts، مع منع تضمينها داخل iframe.
- **لا يتم نشر `wwwroot/auth.html` الموجود لبيئة Development**؛ لا يوجد `UseStaticFiles()` جديد في Staging. الملفان المسموحان فقط هما `darecare-lite.js` و`darecare-lite.css`.
- الـRefresh Token داخل الذاكرة؛ إعادة تحميل الصفحة تعني تسجيل الدخول من جديد، وهذا مقصود للنسخة التجريبية.
- التسجيل أو رفع وصفات أو الحجز يحتاج بيانات **وهمية فقط** على الخدمة المجانية Render/SQLite. قاعدة SQLite مؤقتة ويمكن أن تفقد البيانات عند إعادة تشغيل الخدمة أو تحديثها.
- نسخة ASP.NET في Production **لا تنشر الواجهة**: نطاق العرض مقتصر على Development/Staging.

## فحوصات القبول

- `node --check src/DareCare.Api/wwwroot/darecare-lite.js`.
- راجع `.github/workflows/dotnet-ci.yml`: بناء .NET، اختبارات xUnit، بناء Docker مطابق لـRender، HTTP smoke، ثم GET `/` وملفات assets والتحقق من CSP، ورفض `/auth.html` في Staging.
- تم فحص الواجهة محليًا بمتصفح Chromium على عرض 390 و768 و1440 بكسل، مع تدفق تفاعلي باستخدام **ردود API اصطناعية ضمن الاختبار فقط**. هذا لا يثبت صحة سيرفر خارجي.
- **بعد النشر:** لا تعلن رابط `/` حيًا حتى ينجح فحص GET حقيقي لهذا العنوان ويظهر محتوى الواجهة، مع استمرار `/health/ready` و`/api/v1/services` في الرد 200.

## المتبقي لتطبيق إنتاجي

هذه واجهة MVP لتجربة الربط، ولا تحتوي على دفع، سجل إشعارات متكامل، رفع آمن بوسائل فحص برمجيات خبيثة، تخزين مستمر، تقييمات شاملة أو واجهة إدارة متكاملة. هذه متطلبات منفصلة قبل أي استخدام صحي حقيقي.
