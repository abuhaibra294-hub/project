# DareCare Lite — بوابة إدارة مستقلة باسم alias

## مسارات الدخول
على **نفس دومين API الحالي** (دون دومين فرعي أو استضافة جديدة):
- \`/admin\` — بوابة دخول الإدارة.
- \`/admin/login\` — alias للبوابة نفسها.
- \`/assets/darecare-admin.css\` و\`/assets/darecare-admin.js\` — ملفات الواجهة فقط.
- يوجد رابط "دخول الإدارة" في تذييل الموقع الرئيسي لجميع مقاسات الشاشات.

يُقدَّم HTML وCSS وJavaScript بوضوح من ASP.NET Core في \`Development\` أو \`Staging\` فقط، مثل DareCare Lite الأساسي. لا يضاف \`UseStaticFiles()\` في Staging ولا تُنشر أدوات Development الحساسة.

## الوصول والصلاحيات
هذه صفحة دخول عامة لا تحتوي بيانات إدارة في كود HTML. يبدأ جلب بيانات المستخدمين أو الموافقات **فقط بعد تسجيل الدخول**، والتأكد من:
1. \`POST /api/v1/auth/login\` يُرجع Role = \`Admin\`؛ الحسابات غير الإدارية تُرفض حتى لو كلمة مرورها صحيحة، ويُلغى Refresh Token الذي صدر لها.
2. \`GET /api/v1/auth/me\` يثبت صلاحية Admin من الباك.
3. \`GET /api/v1/admin/overview\` يؤكد صلاحية الدخول لواجهة API المحمية.

جميع مسارات \`/api/v1/admin/*\` نفسها محمية في ASP.NET Core بواسطة \`[Authorize(Roles = AppRoles.Admin)]\`. **إخفاء زر أو تغيير رابط ليس نظام حماية.**

الرموز (Access/Refresh) داخل ذاكرة JavaScript فقط؛ لا تُكتب إلى LocalStorage أو SessionStorage ولا Cookies. إعادة تحميل الصفحة تعني تسجيل الدخول مجددًا. عند انتهاء JWT أو ظهور 401 يُغلق العرض الداخلي. زر الخروج يطلب إلغاء Refresh Token ويزيل بيانات الجلسة من المتصفح.

## الوظائف
- مؤشرات الإدارة: المرضى والممرضون والصيدليات والحجوزات؛ وطلبات التمريض والصيدليات التي تحتاج قرارًا.
- مراجعة الترخيص والمهارات ثم اعتماد الممرضين بعد تأكيد صريح.
- اعتماد الصيدلية بعد قبولها الدعوة، مع منع الاعتماد قبل ذلك.
- استعراض المستخدمين (50 في الصفحة) وتفعيل/إيقاف حسابات غير إدارية، وتأكيد الإجراء.
- سجل الإجراءات الإدارية مع التنقل بين الصفحات.
- تصميم عربي RTL responsive وبدون مكتبات أو CDN، وسياسة CSP مغلقة، و\`Cache-Control: no-store\` و\`X-Robots-Tag: noindex\`.

هذه نسخة MVP لا توفر الإدارة الكاملة لكل عمليات المنصة، ولا تستبدل فحص الترخيص الطبي الحقيقي.

## لو مفيش حساب Admin

**لا تنشئ كلمة مرور إدارية افتراضية أو حسابًا مفتوح التسجيل.** طريقة الباك الحالية توفر Staging Bootstrap اختياريًا فقط:
- \`BootstrapAdmin__AllowOneTimeStaging=true\`
- \`BootstrapAdmin__Email\` ببريد حقيقي يختاره مالك المشروع ولا يخص حسابًا موجودًا من دور آخر.
- \`BootstrapAdmin__Password\` بكلمة مرور قوية وفريدة محفوظة في إعدادات الاستضافة السرية، وليس Git أو README أو Postman.

نظام الـSeeder يرفض تحويل أي مستخدم موجود إلى Admin، ويستخدم ASP.NET Identity مع سياسة كلمة مرور قوية. **يلزم تحديد بريد Admin المقصود من صاحب المشروع قبل تشغيل هذا الخيار.** لا تقم بتشغيل Bootstrap تلقائيًا هنا؛ تغيير إعدادات Render قد يؤدي إلى نشر جديد ومحو بيانات SQLite التجريبية. عند تفعيل قاعدة بيانات دائمة، نفّذ تأسيس الحساب مرة واحدة ثم أزل Bootstrap من الإعدادات.

**قيد Render Free:** SQLite داخل الحاوية مؤقتة ويمكن أن تُعاد تهيئتها مع كل نشر، وبالتالي أي حساب Admin تجريبي قد يختفي. لا تستخدم مستخدمين حقيقيين أو وصفات فعلية؛ يجب توفير قاعدة بيانات دائمة قبل اعتماد هذه الآلية لفريق حقيقي.

## اختبارات التسليم
- \`node --check src/DareCare.Api/wwwroot/darecare-admin.js\`.
- Docker HTTP smoke: \`/admin\` و\`/admin/login\` وملفات CSS/JS والـCSP وCache-Control، و\`401\` لمسار Admin API بدون Bearer Token.
- \`scripts/ci_admin_browser.py\`: اختبار Chromium للدخول بحساب Patient ورفضه، والدخول بحساب Admin، وقراءة المؤشرات، والاعتمادين، وحالة المستخدم، والسجل، وتسجيل الخروج، وفحص مقاس موبايل 390px. جميع الحسابات/السجلات في هذا الاختبار وهمية ومحلية.
- \`scripts/ci_onboarding_booking.py\`: اختبار حقيقي للـHTTP/Identity/قاعدة بيانات منفصلة داخل Docker، فيه Admin مختبَر يوافق على ممرض ويسمح بحجز مريض.
- \`scripts/verify_admin_live.py\`: فحص GET عام فقط **بعد ظهور إصدار Render الجديد**؛ لا ينشئ حسابات ولا يرسل كلمات مرور.

**لا تعتبر الواجهة المنشورة صالحة للدخول الفعلي حتى يتم إعداد حساب Admin حقيقي للتجربة والتحقق من تسجيل دخوله عن طريق مالك المشروع.**
